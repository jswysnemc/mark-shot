## Mark Shot 0.2.0

原生 Rust 版本正式发布，支持 Linux X11、Wayland 和 Windows x86_64。
安装包包含屏幕录制媒体库、对应源码和许可声明。

### 界面与交互

- 矩形、椭圆和形状标记的选中框向外留白，便于看清实际描边颜色及粗细；缩放保持正文边界。
- 从截图侧栏打开设置时，先关闭选区和截图窗口，再进入设置界面。
- 贴图编辑改用单行工具栏，右侧统一最小化、最大化和关闭按钮；进入编辑时隐藏来源贴图，退出后恢复。
- 录屏作为普通工具保留选区，小工具栏调整格式、帧率、倒计时、声音、画质、编码器及光标；明确点击开始才启动采集。
- 设置直接显示有效工具、颜色和目录；恢复默认仍删除覆盖项，浏览或确认未改动字段不会写入默认值。
- 修正扩展列表和 X11 编辑界面的滚轮方向。

### Linux 桌面修复

- 修正 KDE 首帧预读后跨异步运行时的总线连接交接，以及共享缓冲回收后重用旧映射的问题。
- 新增 KDE Wayland 原生窗口快照，支持可见窗口、堆叠顺序和最小化过滤；图像区域识别可独立关闭。
- 全局快捷键门户的空绑定显示为未配置，支持系统配置恢复，不再误报注册成功。
- X11／Xwayland 剪贴板根据服务器请求上限选择直接或增量传输，修正 GNOME 大 PNG 读取停在首块的问题。
- 修正 X11 长截图控制面板交接，以及录屏显示光标时缺少 XFixes 版本协商的问题。

### 验证

- KDE Wayland、GNOME Wayland、Xfce 原生 X11 虚拟机完成截图、标注、贴图编辑、设置、录屏、长截图和桌面快捷键验证。
- Xfce 的 17 个功能流程及三个 X11 服务器故障回归通过；320×512 长截图逐像素一致，MP4／GIF 完整解码通过。
- 大 PNG 和中文 UTF-8 覆盖超过服务器单次请求上限的增量传输，重复读取的像素或字节一致。
- 库测试 1233 项通过。平台安装包与发布文件在流水线完成校验后统一公开，SHA-256 显示在下方文件列表。

### 平台范围

GNOME 原生 Wayland 窗口识别尚不支持，图像区域识别可用。Windows 仍需更多真实设备验证。
本轮虚拟机测试为单屏、100% 缩放和软件编码，没有覆盖多屏混合缩放、硬件编码、实际录屏音频、真实输入法候选或外部 OCR／翻译／上传服务。macOS 暂不支持。

### English

Mark Shot 0.2.0 is the official native Rust release for Linux X11, Wayland and Windows x86_64.
Packages include the in-process recording library, its sources and license notices.

Selection frames now leave space around rectangle-like annotation strokes. Pinned-image editing
uses a single toolbar with matching window controls. Opening settings closes the capture first;
effective defaults are displayed without turning inherited values into explicit overrides.
Recording is a normal tool with parameters in its compact toolbar and an explicit start action.

This release fixes KDE capture connection and buffer reuse, adds KDE Wayland window snapshots,
handles unassigned portal shortcuts, and corrects large X11/Xwayland clipboard transfers.
X11 wheel direction, scrolling-capture controls and recording cursor negotiation are fixed.

Real KDE, GNOME and Xfce virtual-machine workflows were verified. GNOME Wayland window geometry
remains unsupported, Windows remains experimental, and macOS is not supported. The VM coverage
uses one display at 100% scale and software encoding; it does not establish support for every
hardware, audio, input-method or external-service configuration.
