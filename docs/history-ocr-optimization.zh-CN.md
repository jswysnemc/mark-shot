# 历史预览与 OCR 输出的第二轮优化

日期：2026-11-01。基线为 `23e2142`，即已包含上一轮录制、剪贴板和 OCR 运行库回收的版本；本报告的降幅不与 `v0.1.61` 或其他场景直接相加。仅使用生成图片与隔离配置，不访问用户截图、桌面或剪贴板。

## 1. 历史窗口：显示数据与操作原图分离

原路径每次激活窗口都会清空列表、重新生成全部缩略图；即使预览只有数百像素，窗口仍长期持有完整原图。新增生产窗口测试先观察到两个失败：无变化刷新使持久模型索引失效，小窗口保留完整 3840×2160 像素。

复现命令与原始记录：

```sh
QT_QPA_PLATFORM=offscreen ctest --test-dir build -R '^capture-history-window$' --output-on-failure
```

失败日志：`build/optimization-round2/results/history-red.log`。修改后对应测试通过，不靠放宽内存断言规避原图常驻。

### 实现职责

```text
qt/src/capture_history/
  history_preview_cache.{h,cpp}  有界预览缓存、文件版本校验、删除清理
  history_window.{h,cpp}         增量列表刷新、预览更新与调度
  history_window_actions.cpp     按需读取原图，保持操作语义
qt/tests/
  history_preview_cache_test.cpp   容量、命中、失效、尺寸、DPR 和像素一致性
  capture_history_window_test.cpp  实际窗口预览、选择、复制和保存回归
```

- 缓存仅保存指定尺寸的预览，图像成本按 KiB 向上取整，默认上限 8MiB；超出容量的单张预览不进入缓存。
- 缓存依据路径、大小、修改时间与元数据变更时间判断失效；源文件缺失或变成符号链接时不返回旧图。删除历史项或清空历史后清理对应缓存。
- **8MiB 是缓存上限，不是整个窗口内存上限。** 当前显示图、QPixmap、模型条目及调用方继续持有的共享引用另计；首轮 PNG 解码也可能产生临时完整图像。
- 保留未变化的列表项，新增或删除时按文件标识更新并保留已有选择。没有用无限保存所有原图的方式降低重复读取成本。
- 预览按窗口实际物理像素尺寸读取，截图自身 DPR 不参与预览布局；复制、编辑、贴图和另存为分别读取完整原图，保留原图尺寸、透明度和 DPR。
- 连续窗口缩放、分隔条移动会合并为 30ms 后的预览更新。选择变化期间不会继续展示上一个文件的预览。
- 保存对话框保持打开时刻的原图快照，之后切换历史选择不会把另一张图片写入目标文件；这是原有语义，而不是延迟读取当前选择。

### 范围限制

初次生成列表缩略图以及单次 PNG 预览解码仍在 GUI 线程。本轮减少重复解码与原图常驻，不宣称完成全异步历史加载。文件版本使用元数据而非内容哈希；手工恢复所有时间戳的同名同尺寸改写不属于已验证的失效契约。

### Release 完整入口实测

两份 Release 应用和 OCR 插件各自复制到独立目录，插件清单一致。历史目录包含 50 份合成 4K PNG，三轮交错启动，每次十秒；稳定 RSS 取七秒后样本中位数，再取三轮中位数。峰值取内核 `VmHWM`，不是 50ms 采样的最大值。

| 条件 | 内核峰值 | 稳定 RSS |
| --- | ---: | ---: |
| 上一轮已优化版本 | 127.64MiB | 99.41MiB |
| 本轮候选 | 98.45MiB | 67.62MiB |

本场景稳定 RSS 减少约 **32%**，峰值减少约 **23%**。这是实际历史窗口进程的结果，不是从 4K 像素容量推算出的节省量；不能外推为所有界面或任意图片的固定降幅。

## 2. OCR：在原生输出有效期间直接解码

上一轮已经回收 ONNX 运行库，但识别输出仍先从原生张量复制为 `QVector<float>`，再读取完整 `[1,T,C]` 概率矩阵完成字符解码。本轮将解码放入输出张量有效的同步作用域，避免这份完整副本。

```text
qt/plugins/ocr-rapid/
  rapid_onnx_session.{h,cpp}  作用域输出访问，保留需要自有副本的兼容入口
  rapid_rec_decoder.{h,cpp}  概率 argmax、CTC 折叠、置信度和字符跨度
  rapid_rec_result.h         自有识别结果类型，不含原生指针
  rapid_rec_model.{h,cpp}    输入准备与模型调用
qt/tests/
  rapid_rec_decoder_test.cpp  重复字符、空白、空格、并列概率和非法形状
  rapid_onnx_output_test.cpp  真实原生地址、回调结束释放及异常恢复
```

- `visitOutput` 在张量有效期间同步执行回调，回调只能读取借用的浮点数据。正常返回、拒绝或抛异常均由现有 RAII 清理原生张量。
- 检测模型仍使用需要自有数组的 `run` 入口，算法未改写；识别模型返回的文字和字符跨度仍是 Qt 自有值，不跨运行库卸载保留原生指针。
- 解码保持原有最早最大概率、重复折叠、blank、尾部空格裁剪与置信度计算顺序。补充形状、容量和整型边界检查。
- 没有缓存模型、降低输入分辨率、减少识别请求、调整线程数或改变图优化等级；后台异步 OCR 与直接文字拖选不变。

### 真实模型与输出一致性

使用前一轮的密集文字、大文字和空图三个合成样本，新旧插件交错各三次，共 18 次调用。对应的完整 token JSON（文字、坐标、置信度）精确一致。

| 样本 | 原耗时中位数 | 本轮耗时中位数 | 原峰值 RSS | 本轮峰值 RSS |
| --- | ---: | ---: | ---: | ---: |
| 密集文字 | 734ms | 730ms | 138.35MiB | 138.13MiB |
| 大文字 | 282ms | 275ms | 138.22MiB | 138.20MiB |
| 空图 | 148ms | 141ms | 137.80MiB | 138.43MiB |

这些是插件接口级测量，不含完整贴图 GUI。三次中位数不足以将数毫秒差异与系统波动区分，因此**不宣称本轮 OCR 整体峰值或速度显著改善**。已确认的收益是取消完整概率矩阵副本，以及明确输出所有权边界。

真实运行库测试通过代理输出访问接口记录原生指针，确认回调地址没有来自另一个复制数组；分别测试成功、拒绝和异常回调，张量在回调结束后释放，同一会话随后仍可正常推理。

## 3. 验证记录

- Debug 和 Release 的历史窗口、预览缓存、字符解码、原生输出、真实 OCR 插件五个测试目标均通过。
- ASan/UBSan 的预览缓存、字符解码、原生输出和真实 OCR 插件四个目标通过；LeakSanitizer 关闭，系统 Qt/ONNX 未插桩，不据此宣称整个应用无泄漏。
- 窗口测试覆盖原图尺寸与 DPR、复制的完整像素、保存时选择变化及文件删除；合成透明图的缓存预览与原平滑缩放结果逐像素一致。新增 2 倍缩放窗口测试并通过。
- 完整构建通过，全量测试 **191/195** 通过；失败仍为此前的 `annotation-cursor` 与三个 Hyprland 初始化用例，没有修改或跳过这些失败。日志为 `results/full-tests.log`。
- 本轮不修改动态 GIF 调色板、GPU 传输、OCR 裁剪图复制，也没有替换用户已安装的应用。

所有基线二进制、探针、图片、产物 SHA-256 和原始结果保存在忽略目录 `build/optimization-round2/`。对照脚本为 `compare.py`，主要数据为 `results/history-summary.json`、`results/ocr-summary.json` 和 `results/artifacts.json`；正式回归测试保留在仓库中。
