# Qt 界面内存优化

## 范围

本轮只优化 Qt 界面对象和字体列表，不改截图像素、OCR 生命周期或录制后端。
基线包含前两轮尚未提交的历史预览、OCR 输出解码和画布像素共享修改。
不降低截图分辨率，不关闭后台 OCR，不调用内存整理或工作集回收接口。

检查发现，截图窗口在用户尚未使用字体选择功能时已经创建字体弹层。
本机列表包含 2366 个字体系列，每一行还分别创建相同的空白图标或勾选图标。
设置窗口已经按页延迟创建，因此本轮没有重新实现设置页加载，也没有为节省对象数丢弃未提交的设置。

## 实现

```text
qt/src/shot_window_font_panel.cpp      字体弹层按需创建，预览列表统一行尺寸
qt/src/shot_window_text_controls.cpp   文字样式和最近字体逻辑，复用列表图标
qt/src/shot_window_controls.h          窗口持有两张列表图标及其颜色状态
qt/src/annotation/text_size_limits.h   字体面板与文字样式共用字号边界
qt/src/shot_window_property_panels.cpp 首次打开时初始化，完成布局后居中当前字体
qt/src/shot_window_setup.cpp           不再提前创建字体弹层
qt/tests/qt_ui_memory_test.cpp         实际控件的生命周期、交互及缩放回归
qt/tests/gui_memory_scenarios.cpp      字体面板打开、隐藏、再次打开的测量场景
```

- 普通截图、画笔标注和默认文字输入不创建字体列表。用户点击字体按钮时才创建，后续复用同一个弹层。
- 列表沿用原来的字体名称预览和搜索；代理只改变尺寸计算，不替换预览字体。
- 列表不再为行高逐项测量字体。96 DPI 时统一为 28 个逻辑像素，较高逻辑 DPI 按比例增加，避免放大文字后截断。
- 整份列表共用一张空白图标和一张勾选图标；再次打开时保持图标缓存键不变，配色变化时更新勾选图标。
- 面板尺寸及搜索筛选确定后，才把当前字体滚动到中间，避免首次打开和再次打开显示不同的一批字体。
- 图标和列表仍由窗口持有，关闭窗口时随 Qt 对象树释放；不添加跨窗口静态图片缓存。

## 中间方案及修正

仅延迟创建并不能直接交付：普通截图 RSS 只减少约 2 MiB，但字体面板场景峰值从约
150.7 MiB 增长到约 166 MiB。该中间版本和数据保存在本机
`build/optimization-round4/font-lazy-only/` 与 `results/font-lazy-only/`。

后续分别减少字体尺寸测量、共享列表图标，并检查真实可见行。诊断发现，新面板在初始尺寸下滚动，
随后才调整高度；再次打开又重新居中，导致两次加载不同的预览字体。
搜索无匹配结果后再次打开，也可能滚动到整个列表顶部。
新增可见首行一致性断言能够复现该问题，修复后通过。

没有保留未产生收益的 `ensurePolished()` 实验，也没有通过关闭字体预览规避占用。

## 受控窗口测量

两侧使用同一机器、相同 Release 配置、独立配置目录、Qt offscreen、显示比例 1、
生成的 3840 × 2160 图片。每组交替运行三次，表中为中位数，单位 MiB。
测量目录不携带 OCR 运行库和模型，这些数字不包含推理。
RSS 与存活堆分配分别读取，不能混称为同一指标。

| 场景 / 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 普通截图，窗口显示后 RSS | 145.72 | 143.53 |
| 普通截图，窗口显示后存活堆分配 | 80.48 | 75.36 |
| 普通截图，进程峰值 | 153.10 | 151.12 |
| 字体面板首次打开，RSS | 150.56 | 146.63 |
| 字体面板再次打开，RSS | 150.65 | 146.67 |
| 字体面板再次打开，存活堆分配 | 85.82 | 82.54 |
| 字体面板场景全部窗口关闭后，RSS | 87.39 | 83.38 |
| DPR 2 贴图与编辑器同时显示，RSS | 171.03 | 168.73 |

普通截图的 QWidget 数量从 228 降到 215，字体列表也延迟到实际使用时分配。
打开字体面板后仍为 228 个 QWidget，功能没有通过减少可用控件而缩水。

本轮是约 2 至 4 MiB 的 RSS 改善，而不是几十 MiB 的整体下降。
本机字体较多，字体数量较少的环境可能获得更小收益。

## 原生 Wayland 边界

使用独立 D-Bus、Xvfb 和 niri，通过真实 `mark-shot --capture` 入口测量，
两侧携带相同 layer-shell 插件。只截取隔离桌面，不访问用户实际桌面。

静止窗口三轮结果如下，不能只比较总 RSS 中位数来归因：

| 版本 / 轮次 | RSS | Wayland 显示缓冲区 |
| --- | ---: | ---: |
| 基线 1 | 204.36 | 94.94，三张 |
| 基线 2 | 172.66 | 63.30，两张 |
| 基线 3 | 172.48 | 63.30，两张 |
| 优化后 1 | 201.66 | 94.94，三张 |
| 优化后 2 | 201.74 | 94.94，三张 |
| 优化后 3 | 201.64 | 94.94，三张 |

同为三张显示缓冲区时只减少约 2.7 MiB；若一侧有两张、另一侧有三张，
多出的 31.64 MiB 会盖过界面对象收益。本轮不能保证原生截图的总 RSS 稳定下降，
也不能据此宣称用户之前观察到的约 200 MiB 已解决。
显示缓冲区数量可能受创建和绘制时序影响，本轮没有更改 Qt 缓冲池策略。

为避免只观察静止窗口，又在隔离 Xvfb 内移动指针，触发实际截图界面的悬停绘制。
两侧交替测量三轮，每轮均为三张显示缓冲区，结果如下：

| 实际截图交互指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| RSS 中位数 | 204.31 | 201.71 |
| 匿名驻留页中位数 | 53.02 | 51.34 |
| Wayland 显示缓冲区 | 94.94 | 94.94 |

相同三缓冲交互场景约减少 2.60 MiB，约 1.3%。这与受控 Qt 窗口的改善量级一致，
不能用两缓冲与三缓冲之间的差值宣传收益。相关数据文件前缀为 `native-active-`。

## 验证与复现

- 新增测试在旧实现中因字体弹层提前创建而失败。
- 首次打开与重开定位不一致的断言先失败，修正布局顺序后通过。
- 验证默认文字输入、搜索、字体选择、字号、粗体、斜体、面板复用与窗口销毁。
- 验证两张图标覆盖整份字体列表，并跨次打开保留缓存键。
- Release 的界面测试覆盖显示比例 1 / 2，以及逻辑字体 DPI 144，三个目标通过。
- 主题测试改为先通过真实字体按钮创建延迟弹层，再检查浅色、深色与系统主题，没有跳过面板配色断言。
- 检查了隔离生成图上的字体弹层截图；1 倍和 2 倍显示比例下，字体预览及底部控件未出现截断或重叠。
- 字体面板的本机峰值预算设为 149 MiB 时，基线为 150.73 MiB、退出码 1，优化后为 146.64 MiB、退出码 0；该预算不适用于任意平台或字体环境。
- 连续五轮打开字体面板并关闭窗口，每轮 QWidget 都回到 0；优化后关闭时 RSS 为 83.43 至 83.55 MiB，存活堆分配为 11.33 至 11.43 MiB。不据此声称 Qt 全局字体缓存已全部释放。
- GUI 场景、文字标注、主题和三个界面内存测试共六个针对性目标通过。
- 完整 Debug 构建成功；最终全量测试 195/199 通过，剩余为原先的 `annotation-cursor` 和三个 Hyprland 初始化失败。
- 首轮并行测试中，KDE Xwayland 的窗口状态查询曾超时；单独复测及最终全量复测都通过。
- `git diff --check` 和源码行数限制检查通过。

```sh
cmake --build build/memory-regression/build-fixed \
  --target mark-shot-qt-ui-memory-test mark-shot-gui-memory-benchmark --parallel 4
QT_QPA_PLATFORM=offscreen ctest --test-dir build/memory-regression/build-fixed \
  -R '^qt-ui-memory(-hidpi|-fontdpi)?$' --output-on-failure
QT_QPA_PLATFORM=offscreen QT_SCALE_FACTOR=1 \
  build/optimization-round4/candidate/mark-shot-gui-memory-benchmark \
  --scenario font-panel --width 3840 --height 2160
```

`baseline/` 和 `candidate/` 是本机保存的同配置对照二进制；`candidate/` 从 Release 构建目录复制。
原始 JSON、日志、隔离诊断脚本与人工检查的图片在 `build/optimization-round4/`，不纳入源码。
诊断用的 `LD_PRELOAD` 探针只用于检查可见行和截图，没有用于正式内存数据采集。
