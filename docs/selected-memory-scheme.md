# 选用内存方案 R20

2026-11-07 根据最新目标结束继续压低内存的实验，选用 R20 作为主题与 Windows 工作的基础。
全部场景低于 Qt 一半尚未通过，保留失败指标与未验证项。浅色主题和 Windows 原生工作流
调整为最高优先级，不继续围绕低优先级内存样本重复试验。

后续用户实测反馈：长截图内存仍不如 Qt，普通截图内存下降但帧率下降。
下面数据仅代表指定构建与私有固定场景，不能外推为用户场景通过，也不能证明交互性能没有回退。
目前尚未取得该实测场景的构建指纹、长图尺寸和帧时间记录，两个问题继续列为未解决项，
不通过降低画质或忽略卡顿完成内存验收。

候选为 `target/memory-optimized-candidate-r20/mark-shot`，大小 50,103,496 字节，SHA-256 为
`840357941c18b43f84ce178c092e3a3093a49b91c4f2fa2ed4512ef1e407a55f`。
默认功能 release 不依赖 Qt。1,629 项构建输入封存于候选目录 `source-inputs.tar.gz`，
指纹为 `dce8660a8bfe5e675a3ee354d50ae8db3174849932ac7186d090f35665fe4fc3`。
原发布文件没有覆盖，没有提交或发布。

R20 使用单表面合成，最多两个原生缓冲，按最多 1 MiB 交付并消费 CPU 前景。
标注保留稀疏栅格，画笔片段与恢复区域归还零页，背景每次最多读取 2 MiB。
首次原生提交强制恢复完整场景，避免局部面板通知缩小首次损坏范围；两项生命周期
回归在修改前失败、修改后通过，证据为 `target/first-frame-red-r20.log` 与
`target/first-frame-green-r20.log`。

七组非工具原生流程通过，3200×7944 完整长图导出零像素差异，PNG 指纹为
`0e9e8ab02882edb1cdf9fa03eebf7d84d6eef90b7a92918dd970a490eaa409eb`。
工具两次尝试共有十一项有效对照；Qt 文字没有形成满足可见字形条件的终态，原因尚未
确定。画笔、荧光笔、滤镜、放大镜仍各有超标指标，带序号箭头没有对应 Qt 工具基线。
这些边界不影响选用该方案，但不能表述为全部内存验收通过。

工作区 1,351 项通过、19 项忽略，Clippy、格式和差异空白检查通过。三组同构建界面
回归覆盖明暗切换、旧配置、模型引导、独立窗口、滚轮提示、中文贴图菜单和原图保持；
这些回归未覆盖字体选择弹层，其主题残留由后续独立候选修复。
完整原始结果为 `target/memory-verification-r20/result.json`，历史结果仍使用各自原始
构建指纹和清单。
