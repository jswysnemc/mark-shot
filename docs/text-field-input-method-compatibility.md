# 字段输入法与原版对照

## 当前范围

截图编辑器的字体搜索、点字号、十六进制颜色和通用属性步进字段已接入原生
Wayland text-input-v3。独立 OCR 原文与已开启编辑的单元格后来接入同一协议，具体范围见
`docs/window-input-method-compatibility.md`；历史和文件窗口尚未接入。
字段光标闪烁、完整鼠标拖选和全部 Qt 像素一致性仍未完成。

## 原版样本

探针只读链接原版 395 个构建对象，过期依赖为零，原版源码和对象没有修改。
通过真实 `ShotWindow` 字体控件和 `ColorPicker` 取得 43 组场景、192 个状态。
样本为 `tests/fixtures/qt-line-edit-input-method.json`，原始画面与构建记录位于
`target/qt-line-input-final/`。

应用级对照逐项核验正文、字符选择、光标、撤销重做能力、验证状态、点字号与
已经确认的颜色。原版 UTF-16 替换先转换为合法 UTF-8 字节；协议不能表达的
正向跳过替换经过实际字段分派，不把它计为 Wayland 原生投递。
样本还记录 Qt 信号次数和光标矩形；当前应用对照没有核验全部信号次数与 Qt
矩形像素，不能据此宣称全部 192 个状态的视觉完全一致。

| 行为 | 原版实测与当前实现 |
| --- | --- |
| 连续确认 | 单行字段将相邻确认合并，一次撤销恢复原正文和选择；标注正文仍逐次撤销 |
| 初始选择与候选 | 候选开始时删除选择，取消不自动恢复；无效确认与新候选可以保留原选择 |
| 无效混合确认 | `40你` 整批拒绝，不能过滤成 `40` 后应用 |
| 字号完整文本 | 字段保留 ` pt` 后缀，周边文本与显示文本一致 |
| 字号选择与导航 | 初始聚焦选择数字；`Ctrl+A` 和 `End` 可以包含后缀；非扩展方向键跳过后缀内部 |
| 后缀删除 | 删除完整后缀后补回并清理历史；部分后缀删除拒绝正文，但可以保留后缀选择 |
| 字号回车 | 规范化为已确认字号，清理字段历史，光标回到零，并保留原版文字事务提交行为 |
| 颜色确认 | 输入只改变字段；回车或结束编辑才应用颜色，回车后字段撤销不回退业务颜色 |
| 颜色大小写 | 与规范格式仅大小写不同时保留原输入与历史，不强制重建字段 |
| 长度上限 | 颜色字段最多九个 UTF-16 单元，`#AABBCCDDFF` 截为 `#AABBCCDD` |

## 生产结构与隔离

`ui/text_field/` 分别管理局部历史、整批验证和候选状态。
`app/text_input/fields.rs` 按可见字段及显示器选择拥有者，候选不进入搜索过滤或
业务值应用。字段键盘处理优先于仍存在的文字会话，确认与选择不能进入标注正文。
每次新编辑和程序替换重新分配身份，延迟批次不能进入新字段。

周边正文使用已有四千字节借用窗口。字段字形光标按身份、版本、字号、字重与
字体库数量缓存；静止同步不复制全文、不重新排版或发送相同快照。
数字字段发送 Digits，通用步进字段发送 Number，不携带多行提示。
通用步进字段遵循现有有限数值和父控件夹紧行为，尚未完成全部原版验证器对照。

`renderer/line_edit.rs` 将字段文本、候选下划线、选择与光标交给同一字形布局。
颜色选择前景由字形颜色表达，不以第二次文字覆盖代替。
0.75、1、1.2、2 倍测试逐像素核验字段裁切及局部/整帧绘制一致性，覆盖偏移原点。

## 实际验证

- 私有配置工作区 753 项 Rust 测试通过，10 项忽略；118 项 Python 测试通过
- 全部目标与功能的严格 Clippy、格式检查、新增脚本 Ruff 和发布构建通过
- niri/Sway 的 layer/window 四组共 21 个原生投递场景通过，使用同一发布指纹
- 搜索候选实际绘制，已过滤字体列表逐像素不变；连续确认合并撤销，字段文字不进入标注
- 字号数字用途、无效整批、颜色回车与局部撤销通过；最终导出与基准逐像素一致
- 四组静止字段均保持单线程，1.1 秒 CPU 时钟不增加，停止画布提交；未创建 OCR 模型目录
- 同一指纹的 niri/Sway 光标回归通过，动态链接没有 Qt、GTK 或 WebView

证据分别位于 `target/field-niri-r2/`、`target/field-sway-r2/` 和
`target/field-sway-r3/caret/`。测试器等待真实首帧，不以原生激活推断界面已经呈现。
