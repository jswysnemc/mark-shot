# 缺少 Layer Shell 时的长截图

长截图不再因缺少 `zwlr_layer_shell_v1` 在入口处退出。支持 Layer Shell 的合成器继续
使用原输出上的按需焦点浮层；其他环境使用标准 xdg-shell 的透明父窗口和受屏幕边界
约束的控制表面。控制表面只提交面板像素，不覆盖整个输出，也不申请菜单输入抓取。

这条路径需要支持弹出表面重新定位的 xdg-shell 版本 3。捕获协议与显示角色独立，
原始图像仍来自原输出的持续捕获会话。实际 GNOME、KDE 与其他桌面运行矩阵尚未
完成；私有协议缺失验证不能代替这些桌面的授权界面和窗口管理行为。

## 角色、布局与输入

表面创建从覆盖层主文件拆到 `src/backend/wayland/overlay/presentation.rs`。
`utils/scroll_popup.rs` 持有标准父窗口、控制角色、位置约束和尺寸请求编号；
`overlay/scroll_window.rs` 将完整画布裁为面板，
`overlay/state/scroll_window.rs` 在配置完成后提交缓存图像。

父窗口先接受配置并映射透明缓冲，再创建子角色。控制区域增长时请求重新定位，等待
合成器配置后才提交对应图像。过期配置不能解除新请求的等待。合成器压缩后的尺寸
限制只作用于面板，选区位置和捕获裁切继续使用原输出。绘制、按钮命中与预览共用
`constrained_layout()`，避免缩小窗口后使用旧坐标。

普通窗口指针先映射到面板画布。方向握柄拖动期间保留开始时的坐标基准，面板原点
变化不能重复累计物理指针位移。左键按下和同按钮内释放交付动作，右键与中键保留
原有隔离策略。底层页面继续接收滚轮，点击页面后仍可接收方向键。

合成器可能在点击底层页面时关闭非抓取弹出表面。应用只重建控制表面，保留透明父
窗口、捕获授权、拼接图像和暂停状态；这条通知不作为截图取消。用户关闭父窗口或
使用取消按钮才结束会话。保存时释放控制表面，取消保存后在同一输出恢复。

## 捕获区域保护

标准 xdg-shell 不提供普通窗口全局位置。应用从实际提交的面板像素中抽取不透明
平色及颜色边界，定位控制表面。最多保留六组最近实际提交的稀疏样本，覆盖按钮按下
和释放期间仍在途的旧缓冲，不为此保留多份完整面板图像。

控制区域与选区重叠，或者所有样本都无法确认位置时，应用释放控制表面，拒绝当前
帧并请求干净帧。暂停、复制、保存和标注等待干净帧完成，隐藏期间停止预览绘制。
静止后暂停并恢复操作界面；恢复捕获后再次检查实际位置。面板识别允许两级颜色值
差异以适应显示采样，原始长图比较不设置像素误差容限。

## 验证方法与失败记录

`scripts/wayland_layer_shell_filter.py` 只在已验证的私有 Sway 中提供独立 Wayland
套接字。代理隐藏 Layer Shell 的注册表事件，保持其余对象与全局标识，转发双向文件
描述符。`wayland_protocol_filter.py` 负责分片消息解析。四项独立套接字测试覆盖分片、
无关消息、非法长度、真实共享内存描述符和部分写入。

应用连接代理，测试页面与独立原始截图客户端连接同一私有合成器的原套接字。这样
验证真实协议缺失，同时避免让生产捕获实现生成期望图。验证器使用实际保存按钮颜色
定位控件，主题切换等待像素呈现，暂停判断读取可见图标。暂停请求计数同时涵盖
image-copy 和 wlr-screencopy。代理正常结束的对端连接重置单独计数，传输错误仍令
验证失败。

保留的失败现场包括：

- `target/layerless-scroll-before-r2/`：旧候选因缺少协议拒绝长截图
- `target/layerless-window-live-probe-r1/`：直接采用透明全屏窗口遮挡或污染页面
- `target/layerless-popup-live-probe-r1/`：父窗口映射前创建子角色，没有收到控制配置
- `target/layerless-matrix-scale1-r1/`：页面点击关闭控制表面后错误结束会话
- `target/layerless-matrix-scale1-r2/`：只使用最新样本导致按下期间隐藏面板，释放没有送达
- `target/layerless-final-scale15-r1/`：验证器在分数采样后误判暂停图标

最终候选、测试结果、原生流程、暂停资源、输入指纹和依赖检查统一记录于
`target/verification-layerless-scroll-r1/result.json`。完整图像比较涵盖纵向、横向、
选区往返、预览、主题、保存取消、标注交接、实际保存和大选区隐藏。持续会话与
原图交接说明见[持续捕获会话](continuous-capture-compatibility.md)。

最终候选为 `target/layerless-capture-candidate-r2/mark-shot`，SHA-256：
`2c86abb750cc54e1665f3fb4a7c323d52cf264d7167b0c2be2d46897effc3cc9`。
image-copy 和 wlr-screencopy 各在一倍、1.5 倍执行普通窗口完整矩阵，原浮层也执行
对应四组矩阵。普通窗口一倍纵向为 280×712、横向为 664×280；1.5 倍纵向为
420×1068、横向为 996×420。原生方向拖动从 `(40,40)-(320,320)` 移到
`(40,60)-(320,340)` 后原样恢复，最终导出包含全部原始像素。

大选区在隐藏、静止恢复、继续捕获后保持同一图像，一倍最终为 1264×928，1.5 倍为
1256×992。暂停样本保持 3 个线程、19 个文件描述符，CPU ticks 和 RSS 均未变化；
四组普通窗口样本 RSS 为 67,500–80,328 KiB。新候选还通过编辑器明暗主题、三类
滚轮数值气泡及贴图中文菜单回归。贴图八个静止样本均为单线程，CPU 和缓冲提交稳定。

默认工作区 1232 项通过，全特性 1233 项通过，各忽略 19 项。严格 Clippy、格式、
Python 语法与相关 Ruff 检查通过，代理四项测试通过。1628 项源码、资源、脚本及
构建清单核对一致，最终候选无 Qt 动态依赖。该候选尚未替换发布文件或系统入口。

上述验证属于私有单输出环境。实际多输出、其他合成器、全部 Qt 光栅细节及最终
冷启动审计仍需完成，整体重写目标保持进行中。
