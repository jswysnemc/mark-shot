# 录制 CPU 与内存基准

以下为旧外部录制器架构的历史基准。新的进程内架构结果见文末，不能混用两者数据。

日期：2026-11-11。此前功能测试没有采集 CPU/RSS/PSS；本文是本次补测，使用已交付的
`43534bd7e8fd8a4095775890199242806a10132e` Linux release 包，不使用调试构建。

## 条件和口径

- AMD Ryzen 7 8845H，8 核 16 线程，Linux 隔离 Niri/wlr-screencopy 桌面
- 录制区域 1280×720，30 帧，MP4/H.264，软件编码，均衡质量，无音频、无指针
- 静态场景为空工作区；动态场景为全屏 FFplay `testsrc2=size=1280x720:rate=30`
- 每场景采样约 20 秒，间隔 0.5 秒，录制开始和场景切换完成后采样
- 统计录制控制进程及全部子进程，录制时包含随包 wf-recorder；排除 Niri、PipeWire、FFplay、采样器
- CPU 以单个逻辑核心 100% 为口径；RSS 累加可能重复计入共享页，PSS 按比例分摊共享页
- 采样期间没有进行本任务的编译，四组 SwapPSS 均为 0；不计 GPU 显存、功耗和桌面系统整体开销

## 实测

| 状态 | CPU 平均，单核 % | RSS 平均 MiB | RSS 峰值 MiB | PSS 平均 MiB | PSS 峰值 MiB |
| --- | ---: | ---: | ---: | ---: | ---: |
| 控制窗口空闲 | 0.00 | 39.86 | 39.86 | 30.35 | 30.35 |
| 静态 720p30 | 18.00 | 100.86 | 100.87 | 86.55 | 86.58 |
| 动态 720p30 | 22.30 | 108.14 | 108.14 | 92.94 | 92.96 |
| 暂停 | 0.50 | 108.21 | 108.21 | 93.01 | 93.03 |

动态录制的 22.30% 单核占用，相当于本机 16 个逻辑核心总容量的约 1.39%。暂停后保留编码
缓冲，不应据此预期内存立即下降。这是单机单次稳态样本，不是跨设备平均值，也不覆盖启动、
保存导出、硬件编码或 Windows。此前另一轮采样期间出现明显驻留页下降，其数据未用作本表。

## 复测和证据

```sh
uv run --python 3.14 python scripts/recording/benchmark.py RECORDING_PID \
  --seconds 20 --output target/recording-benchmark.json
```

脚本读取 `/proc`，递归汇总进程树，并记录进程启动时钟以避免 PID 重用造成错误。
应在编码子进程启动后采样；采样区间新建或退出的子进程可能缺失部分 CPU 时钟，不能用来
测量启动或导出过程。RSS/PSS 仅统计驻留页，SwapPSS 单独列出。

原始逐次样本位于本地 `target/code-scan-evidence/{idle,static,dynamic,paused}-controlled.json`。
成品为 `/tmp/mark-shot-recording-benchmark/videos/Recording_2026-11-11_18-14-31_000.mp4`。
FFprobe 核验编码、尺寸与帧率，抽帧核对静态和动态图像；验证命令不包含被测录制进程。

## 进程内架构基准（2026-11-12）

基于当前 `feat/native-barcode-scanning` 工作区的 release 构建。Ryzen 7 8845H，AMD Radeon 780M，
隔离 Sway/GLES2，ext-image-copy；1280×720、30fps、均衡质量、无音频无指针。
静态为空工作区，动态为独立 FFplay testsrc2。每组20秒，采样间隔0.5秒，单核100%口径；
只统计录制控制进程及其子进程，排除合成器、测试画面、音频服务；采样期间不编译。
全部样本仅有一个应用进程、SwapPSS 为0。实际成品动态段逐帧核验均为30.0fps。

本机720p30下，硬件模式没有降低应用CPU，RSS还包含更多驱动映射；显存不在RSS/PSS内。
不能据此推断高分辨率、其他GPU或整机功耗表现。软件与硬件编码器画质目标不等价；
旧基准使用Niri、wlr-screencopy和libx264，不能据此宣称同画质性能提升倍数。
较早的13fps调度错误样本已废弃，不纳入本表。
