# OCR 结果窗口界面语言

本文件记录 Rust 结果窗口的原版界面语言接入。全部构建、原版采集和合成器运行只在
本地执行，不修改原版 Qt 工程或用户配置，不提交、不推送、不发版。

## 原版依据

原版 `ui/i18n.cpp`、`ui/interface_language_config.cpp` 和
`ui/i18n_task_windows.cpp` 定义语言选择及文案。语言选择顺序为：

1. 非空 `MARK_SHOT_LANG` 环境变量
2. 非空 `ui.language`，兼容 `english`、`chinese`、`system` 及原版别名
3. 旧版顶层 `language`，仅在新键缺失或为空时使用
4. 系统语言；中文区域使用简体中文界面，其他语言使用英文界面

未知的非空环境覆盖值使用英文；未知的非空配置模式跟随系统，不能越过新键读取
旧键。环境变量支持 `zh` 前缀及中文区域名；配置别名严格按原版解析，不能混为同一
组规则。支持读取已有 JSON 的语言字段，不据此认定全部 JSON 启动和迁移已完成。

`tests/fixtures/qt-ui-language-reference/main.cpp` 只读链接完整原版窗口，使用隔离
配置和本地固定命令采集两种语言、五种宽度、七种状态，以及每种语言 63 个文案键。
本轮完整采集为 `target/qt-ui-language-r5/result.json`，冻结记录为
`tests/fixtures/qt-ui-language.json`。此前完整标题栏记录继续提供每种语言 117 个
状态，合计 234 个布局状态。

原版没有翻译 `Always on Top: On`、`Always on Top: Off` 这两个文案键；查询接口
保留原文，不凭主观判断补充与原版不同的提示。标准错误中的 `Provider` 同样保留
原版中文表实际使用的写法。

## 文案与几何

中文页签均为 42 个逻辑像素，不能沿用英文的 43、48、95 像素。复制按钮常态、
成功及失败宽度分别为 62、74、87 像素，英文仍为 68、78、101 像素。表格复制常态
保持 68 像素；失败时中文为 75 像素，英文为 90 像素。

表格标题宽度为英文 34、中文 26 像素；统计分别从 48、40 像素处开始，而不是原生
实现此前固定使用的 54 像素。标题、统计、复制入口之间各保留 6 像素间隔，绘制按
控件矩形裁切。二十个真实表头状态分别覆盖两种语言、五种宽度和复制失败反馈。

“目标语言”标签宽 48 像素，英文标签宽 95 像素；语言输入分别从 64、111 像素处
开始。宽度小于 480 像素时隐藏标签、620 像素处分栏切换等原版断点不因翻译改变。

标题、页签、复制反馈、表格统计、原图菜单、编辑菜单、快捷键子菜单、语言选项、
译文标题、译文占位文案、字符统计、标准翻译提示和保存失败反馈采用原版中文。界面
字形在初始化时定向补充，不枚举整个系统字体库，不增加等待线程或配置观察线程。
缺少原版字体时仍使用已有系统回退，不能据文案及逻辑几何测试认定字形或像素一致。

## 业务数据隔离

识别正文、译文、自由目标语言、服务名称和任意错误详情不作为界面文案翻译。
预设选项显示“英语”“日语”等原版标签，但持久配置和实际命令分别使用稳定名称
`English`、`Japanese`。当前界面标签与稳定名称都能识别；未知自由输入保持原样。

编号参数按原版 `%1`、`%2` 格式替换。参数值不再次翻译或替换，因此业务文字中的
`Copy %1`、`%2` 等内容不会因为界面语言改变。复制正文和普通编辑器选区也不经过
界面字典。复制反馈继续保存原始状态及原版期限，只有绘制时转换文案。

## 实际运行入口

```sh
uv run --no-project --with pillow --with numpy python scripts/wayland_text_sway_runtime.py \
  --root target/private-ocr-language -- \
  uv run --no-project --with pillow --with numpy python scripts/wayland-ocr-localization.py \
  --binary target/release/mark-shot --root target/ocr-language-verification
```

`--language-source` 可指定 `config`、`legacy`、`environment`、`system`。每次必须
使用新目录；运行器不连接用户的 Wayland 套接字。Sway 已完成四种来源的优化构建
验证，覆盖真实中文输入、候选不进入复制正文、译文保持、目标标签与请求稳定值、
表格和原图菜单、快捷键子菜单、撤销重做、保存失败及期限到期。

验收记录存放于 `target/ocr-localization-local-r1/validation.json`。原版采集、源码
指纹、运行结果和私有进程退出记录分别保存，旧构建与失败目录不加入成功矩阵。

本轮固定优化构建为 `target/validated-binaries/ocr-localization-r1/mark-shot`，SHA-256：
`28ac0c92d6def2c1b07ff784c5aa18e4195e9f0001b459e8bdaa2b2351b936d9`。
运行前后都核对该副本指纹，防止构建替换二进制后把旧进程误记为新构建。

## niri 未通过场景

私有 niri 中，选取语言后第一次点击语言输入框会重新打开菜单，输入法上下文因此
失活。失败保留于 `target/ocr-localization-debug-niri-r1/` 等目录，未放宽确认文字、
选区或焦点断言，也未把切换输入后端作为成功替代。

实际窗口查询证明窗口位置和尺寸没有改变；私有虚拟指针请求也确实发送了输入框
坐标。改用同一私有 Xvfb 的指针仍复现该问题。只读构建原版中文 Qt 窗口并执行相同
步骤后，也观察到菜单重新打开，记录为 `target/ocr-localization-qt-focus-niri-r2/`。
这项比较说明问题不只出现在本轮 Rust 本地化实现中，但不足以认定全部 niri 环境或
输入路径均正常。完整 niri 中文场景仍未通过。

## 剩余边界

- 原版 Qt 与 Rust 的完整 Wayland、主题和逐像素对照尚未完成
- niri 语言选择后重新聚焦的原因及可靠实际输入矩阵仍需验证
- 本轮未完成工具提示、完整焦点遍历、光标闪烁和原文占位提示绘制
- 其他窗口的中文界面、设置、上传、扩展、托盘及迁移仍未完成

本轮不代表整体重写完成，也不将单个合成器的通过结果扩展为全部 Wayland 桌面通过。
