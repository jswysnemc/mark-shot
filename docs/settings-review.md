# 设置界面审阅与评估

审阅日期：2026-11-09。基线为当前工作区，包含尚未提交的设置、翻译、工具栏与 OCR 改动。

## 结论

设置界面需要围绕配置语义进行定向重构。优先解决“显示什么值、修改何时保存、保存后何时生效”，然后调整信息分类和页面布局。

现有原生窗口、SVG 图标、下拉浮层、滚动条和原子写入具有复用价值。主要问题集中在有效值推导、编辑状态、搜索索引和业务页面之间的行为差异。仅调整颜色、圆角和间距无法解决这些问题。

本次只新增评估文档，未修改业务代码或用户配置。以下区分实际交互复现、源码确认与设计建议。

## 配置链路

### 配置来源和优先级

1. 路径选择依次考虑 `--config`、`MARK_SHOT_CONFIG_DIR`、已有原生 TOML、兼容 JSON 和默认路径。
2. 启动时将文件与类型默认值合并，处理兼容字段、主题和数值约束，再应用部分命令行覆盖，保存到 `Config` 的启动快照。
3. 设置窗口重新读取配置文件并转换为 `serde_json::Value`；通用页面、翻译页面和工具栏页面分别构造显示状态。
4. 运行时还存在其他优先级：语言环境变量、工具默认值继承、上次会话的放大预览状态、翻译厂商字段与共享字段及环境变量。

这些优先级没有形成统一的界面表示。当前表单主要展示文件解析结果和页面自行补出的默认值，没有稳定区分“显式配置”“继承值”“实际有效值”“本次进程覆盖”。

主要依据：`src/config/paths.rs:14`、`src/config/loading.rs:303`、`src/config/startup.rs:26`、`src/features/preferences/window.rs:103`、`src/translation/resolve.rs:108`。

### 写入和运行时应用

| 层次 | 现状 | 影响 |
| --- | --- | --- |
| 文件更新 | 共用 `persistence::update`，锁内读取最新内容，临时文件同步后替换 | 可保留；避免部分写入，减少多窗口覆盖其他字段的问题 |
| 通用设置 | 字段校验后写入，再重新解析并更新共享快照 | 直接维护全局状态文字，缺少字段级保存结果 |
| 翻译设置 | 独立的嵌套字段合并、校验、重新读取和反馈逻辑 | 底层共用文件锁，但提交语义与通用表单不同 |
| 工具栏 | 共用通用保存入口，再刷新本地预览 | 拖动释放后保存；有独立恢复默认能力 |
| 运行时 | 启动只读快照、可更新共享快照、按业务重新读文件并存 | 生效范围必须按字段定义，不能用一条底栏提示概括 |

依据：`src/config/persistence.rs:25`、`src/config/preferences.rs:13`、`src/features/preferences/window.rs:187`、`src/config/translation/preferences.rs:7`、`src/features/preferences/toolbar/input.rs:17`。

已确认的生效方式：

- 主题在设置窗口保存后更新当前进程配色；从截图内进入设置时，返回会刷新编辑器主题。
- 工具栏布局、默认完成操作、选区放大预览、选区完成后工具，在返回当前截图会话时比较并应用变化。
- 当前截图已经完成捕获，指针是否写入截图等捕获参数不能追溯修改这张截图。
- OCR 运行方式由截图会话初始化时构造的运行对象持有，单纯保存不会重建该对象；引擎选择另有动态读取路径，不能把全部 OCR 字段归为同一种生效方式。
- 日志对象在进程启动时初始化，保存日志级别没有重新初始化该对象。
- 翻译、历史策略有独立的重新读取入口，不能假定另一个设置进程修改后，所有现有窗口都按相同时机更新。

依据：`src/features/preferences/runtime.rs:6`、`src/app/event_loop.rs:103`、`src/app/capture_setup.rs:133`、`src/ocr/engine_choice.rs:43`、`src/logging.rs:51`、`src/config/translation.rs:106`、`src/config/history.rs:102`。

## 问题与优先级

P1 表示配置正确性或输入保留问题；P2 表示重要的可发现性、操作一致性和布局问题。

### P1：页面默认值不能代表实际有效值

**实际复现与源码确认。** 未设置 `log.level` 时，高级页面显示“关闭”。原因是 `Preferences::value` 对缺失的枚举字段直接使用第一个选项，而日志选项的第一项是 `off`。运行时默认文件日志级别为 `Info`，默认终端级别为 `Error`。

同一逻辑还影响工具继承：如果只设置 `startup.default_tool = "pen"`，没有单独设置普通截图和图片编辑工具，启动解析会继承画笔，但设置页面分别显示首个候选“选区”和“选择标注”。后一个例子为源码推导，未实际启动截图验证。

**建议：** 让显示值与实际解析规则共用来源；显式显示“继承默认”“由环境变量覆盖”等状态。不能把缺失值转换成一个看似已配置的普通选项。

依据：`src/features/preferences/window.rs:103`、`src/features/preferences/catalog.rs:393`、`src/config/sections.rs:491`、`src/logging.rs:12`、`src/config/startup.rs:26`。

### P1：未保存输入会在导航时静默丢失

**实际复现。** 搜索保存目录，输入 `/tmp/audit-unsaved-directory`，不按 Enter，切换分类，再搜索目录，字段恢复为 `screenshots`，文件也未记录输入，期间没有未保存提示。

通用页面切换分类、点击搜索或进入其他文本字段会清除或替换编辑器。翻译页面内部切换字段会先提交，但离开分类时调用 `cancel()`，同样丢弃草稿。两个页面对相似动作执行不同规则。

**建议：** 统一字段状态和导航规则。开关、选项即时保存；文本在 Enter 或离开字段时校验提交；校验失败保留草稿并定位错误；Esc 明确取消当前字段。关闭窗口和切换页面必须遵循同一规则，不能默默清空。

依据：`src/features/preferences/window.rs:295`、`src/features/preferences/translation/input.rs:216`、`src/features/preferences/translation/state.rs:254`。

### P2：全局搜索仅覆盖通用目录

**实际复现。** 翻译页使用 Ctrl+F 搜索“模型”，页面显示“未找到匹配设置”。搜索“翻译服务”“接口密钥”或工具栏配置也无法到达对应专用字段。

搜索只遍历 `ENTRIES`，同时非空搜索会关闭翻译与工具栏专用页面。界面文案却承诺“跨分类查找”。

**建议：** 搜索注册所有页面及业务字段，结果显示所属分类；点击结果跳转并定位真实控件。复杂编辑器保留原页面，不必复制到通用搜索表单。

依据：`src/features/preferences/window.rs:93`、`src/features/preferences/window.rs:133`、`src/features/preferences/shell.rs:57`。

### P2：翻译服务的查看、配置与启用没有分离

**源码确认。** 点击服务卡片会立即保存 `provider`；切换到其他服务还会清空命令覆盖。修改某个服务的地址、密钥或模型时，也会写入该服务为当前提供方。

自动模式在页面初始化时转换成具体服务的选中状态，服务列表没有“自动”选项。用户难以辨认当前来自自动选择还是显式指定，也无法在界面中恢复自动模式。界面没有区分“当前使用”“尚未配置”和“正在查看”。

**建议：** 分开维护正在编辑的服务与实际启用的服务；保留自动选择的真实语义；显示配置状态。模型目录查询是目录能力，不能据此宣称翻译请求已经验证成功。

依据：`src/features/preferences/translation/state.rs:49`、`src/features/preferences/translation/state.rs:161`、`src/features/preferences/translation/state.rs:225`。

### P2：保存、校验与生效提示缺少字段归属

**源码确认。** 当前只有一个全局字符串 `status`。普通保存统一提示捕获与引擎启动选项下次截图生效；翻译保存只显示“已保存”；工具栏另有返回截图生效提示。错误位于底栏，按宽度截断，字段本身没有错误状态。

文件写入、运行时重新读取和表单刷新分为连续步骤，后两步失败也统一显示保存失败。这不能精确表达“文件已保存，但应用失败”的状态。该情况属于实现上的错误处理缺口，本次没有注入故障复现。

**建议：** 字段旁显示校验错误、保存结果和生效阶段；底栏只保留简短汇总。明确区分写入失败与写入成功但应用失败。日期格式提供最终文件名预览，目录显示解析后的实际位置。

依据：`src/features/preferences/window.rs:187`、`src/features/preferences/translation/state.rs:150`、`src/features/preferences/shell.rs:262`。

### P2：分类负担不均，翻译页首屏效率偏低

**实际视觉检查。** 900×640 时，翻译内容视口高约 470 个逻辑像素，服务选择面板高 250，超过一半。密钥、模型和请求选项位于首屏之外。580×420 虽已切换为下拉选择并避免重叠，但首屏只能容纳服务和目标语言。

“截图与标注”同时承载 11 项设置，文件保存排在第五组；外观、高级页面却很短。统一的 68 像素行高、分组标题和间隔进一步增加长页面滚动量。

**建议：** 所有窗口宽度默认采用紧凑服务选择器，优先展示当前服务的必要配置；高级请求选项折叠。将保存与历史独立分类，减少在截图行为页面中寻找保存目录的成本。保留现有左右布局及窄窗口叠放能力。

依据：`src/features/preferences/translation/layout.rs:61`、`src/features/preferences/layout.rs:84`、`src/features/preferences/sections.rs:49`。

### P2：设置入口不能完整支持现有业务配置

**源码及界面确认。** OCR 页只有引擎、运行方式和设备，看不到运行库或模型安装状态。项目已有模型引导和资源面板，可以复用这些能力。快捷键页只列出 8 个动作，历史、设置、识别及多数标注动作未收录；录入新按键会替换原有组合，没有清除绑定或恢复默认的统一操作。

通知关闭后，缩略图选项仍可修改且不说明此时不生效。通用设置缺少字段级恢复默认。现有导出、上传、历史限制等配置还需要明确哪些进入统一设置、哪些由业务窗口管理；不建议直接把所有底层参数暴露给用户。

**建议：** 建立可见配置清单和必要的跨页面入口；OCR 显示资源状态与管理动作，快捷键从现有动作目录派生，关联字段表达依赖关系。

依据：`src/features/preferences/catalog.rs:171`、`src/keys.rs:83`、`src/features/ocr_model_guide/mod.rs:9`、`src/ui/model_popover/setup.rs:79`。

### P2：键盘操作缺少统一焦点模型

**源码确认。** 通用列表的 Tab 只遍历字段，没有导航与反向遍历的完整路径；翻译页未编辑时 Tab 总是打开服务菜单，菜单中的 Tab 又用于关闭；工具栏支持删除和移动已选项目，但没有完整的键盘选取路径。

现有测试验证了通用列表 Tab 后控件可见，没有证明仅用键盘可以完成所有设置任务。

**建议：** 统一导航、搜索、字段、菜单和操作按钮的焦点顺序；支持 Shift+Tab；视觉焦点应与鼠标悬停区分。专用编辑器通过同一焦点接口接入。

依据：`src/features/preferences/window.rs:515`、`src/features/preferences/translation/input.rs:435`、`src/features/preferences/dropdown/input.rs:145`、`src/features/preferences/toolbar/input.rs:194`。

## 建议的模块边界

当前设置目录最大文件为 `window.rs`，589 行；本次检查的相关设置文件均未达到 750 行拆分阈值。重构重点是职责和语义复用，不是机械增加文件数量。

建议按下列边界演进，保留现有专用页面和可靠持久化基础；这里只列出主要文件，不表示本次实施迁移：

    ├── catalog.rs             # 聚合字段定义、分类与生效说明

## 重构验收依据

- 未显式配置、继承、环境覆盖和显式配置均能正确呈现；日志与默认工具不再显示错误值。
- 文本字段在 Enter、Tab、切换分类、进入搜索和关闭窗口时遵守统一规则，错误或未提交输入不会静默消失。
- 搜索可以定位翻译模型、密钥、工具栏及 OCR 资源入口，并能返回实际控件。
