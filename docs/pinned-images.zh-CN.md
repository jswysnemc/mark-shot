# 贴图与剪贴板

## 入口

- 截图或编辑图片后，使用工具栏的贴图按钮或 `Ctrl+P`
- 托盘菜单选择“剪贴板贴图”
- 已有贴图获得焦点后，按 `Ctrl+V` 创建新的剪贴板贴图
- 命令行：`mark-shot --pin-clipboard`
- 本地图片：`mark-shot --pin-image path/to/image.png`

剪贴板同时包含图片和文字时优先使用图片。文字保留换行，按当前主题排版；HTML 不会作为富文本执行，也不会加载远程图片。文字上限为 20,000 个 UTF-16 代码单元，文字画布高度上限为 4,096 像素，图像数据上限为 64 MiB。超出限制会提示错误，不截断内容。剪贴板贴图不会自动加入截图历史。

## 鼠标与文字识别

- 贴图显示后在后台异步识别文字，不等待鼠标点击
- 从已识别文字区域开始左键拖动：选择文字，无需修饰键
- 从其他位置开始拖动：立即移动图片；识别完成前也按移动处理，OCR 完成不会改变正在进行的拖动
- `Ctrl+C`：复制已选文字
- 右键“复制图片文字”或“翻译”：显式请求 OCR 或翻译
- 滚轮：缩放；双击文字：选中整行；双击其他位置或按 `Esc`：关闭

启用“拖选复制文字”后，只要 OCR 功能开启，就会在后台准备文字位置。这项准备工作不会自动翻译，也不会弹出后端缺失通知；显式开启的“自动 OCR”和“自动翻译”仍按原设置处理。关闭 OCR 功能可禁止后台识别。未选中的识别区域不再铺背景，只有实际选中文字显示高亮。

## Linux 桌面差异

### niri 与支持 layer-shell 的桌面

置顶贴图沿用 layer-shell 覆盖层，不依赖托盘常驻。截图编辑窗口关闭后，贴图自身维持进程生命周期。托盘菜单由桌面宿主显示，不保证 Mark Shot 获得键盘焦点。托盘或独立命令行进程无焦点且不持有剪贴板时，会绕过 Qt 的旧选择缓存，通过 `wl-paste` 读取当前剪贴板，因此该场景需要安装 `wl-clipboard`。

### GNOME

GNOME 不向普通客户端提供 layer-shell。贴图仍然使用普通窗口，由随包提供的 `mark-shot-scroll-helper@snemc.org` 扩展维护置顶状态。每张贴图使用唯一标题，扩展会等待窗口出现，并跟踪置顶状态变化，避免误改设置窗口或其他贴图。

需要更新并重新启用 GNOME 扩展，才能使用新的窗口跟踪和滚动预览主题支持。旧扩展仍能使用原有滚动预览接口，但不具备新增行为。

置顶不表示覆盖锁屏、系统界面或所有全屏应用。GNOME 下无焦点进程可能无法读取剪贴板，`wl-paste` 也不保证可用；此时可先激活已有贴图，再按 `Ctrl+V`。扩展置顶逻辑已有信号模拟测试，真实 GNOME 桌面仍需验证。
