# 单实例截图与命令转交

普通截图和全屏编辑已共用同一 Wayland 会话占用。再次启动后，新进程向已有实例发送
截图命令并退出；活动编辑器保留冻结图像、标注、选区和辅助窗口。完整重写目标仍在进行，
本次没有实现常驻托盘。

## 原版依据与行为

参考 `../mark-shot/qt/src/ipc/single_instance_ipc.cpp` 与 `qt/src/main.cpp`：

- Qt 使用一行 JSON 表达 `capture`、`fullscreen`、`allOutputs`、`captureDelayMs` 和录制控制
- 尚未开始的延迟截图共用一个调度器，新请求替换期限和截图参数
- 已有截图窗口或正在等待捕获门户时，重复命令不会叠加截图会话
- 命令确认后，重复启动进程退出

旧候选在普通截图活动期间再次启动会创建第二个覆盖层。原始失败证据保留在
`target/single-instance-reproduction-r1/result.json`；本次相同复现确认首个进程仍活动，
第二个进程以零状态退出，并且没有提交图形缓冲。

## 本次实现

```text
src/features/single_instance/
├── request.rs       # 原版 JSON 字段、截图计划与有限回复
├── session_path.rs  # 合成器身份、私有地址和文件类型校验
├── owner.rs         # 生命周期占用、启动竞争和请求转交
├── peer.rs          # 单条请求、非阻塞收发与客户端期限
├── server.rs        # 监听、八个客户端上限及描述符快照
├── state.rs         # 延迟替换、开始确认和活动截图保护
├── context.rs       # 当前截图及辅助窗口的控制范围
└── tests/           # 调度、传输、路径和上下文回归

src/cli/single_instance.rs                 # 普通截图入口
src/backend/wayland/overlay/poll_sources.rs # 共用原生阻塞等待
src/backend/wayland/window/single_instance.rs # 辅助窗口的 calloop 事件源
```

作用范围为 `Mode::Editor`、没有图片且没有指定输出名称的启动，包含 `--capture` 和
`--fullscreen`。图片、快捷捕获、OCR、长截图和指定输出名称的入口继续独立运行。

地址使用 `$XDG_RUNTIME_DIR/mark-shot-instance/capture-<compositor_pid>.sock`。合成器 PID、
UID 来自当前 Wayland 连接的内核对端身份；运行目录必须属于当前用户且权限为 0700。
套接字权限为 0600，普通文件锁覆盖整个截图生命周期。仅在取得锁且旧地址无法连接时
恢复失效套接字；正常退出只删除本次设备号与 inode 对应的路径。

启动、捕获准备和延迟阶段复用当前线程 Tokio 服务。覆盖层把控制描述符与 Wayland、
主选择和后台通知放入同一次原生等待。另存为等辅助窗口使用 calloop，登记独立描述符
副本，并在注销后释放副本。本次没有增加常驻工作线程或周期空转。

每条请求最多 16 KiB，同时最多保留八个客户端，客户端一秒内必须完成。完成回复后
立即关闭连接；坏 JSON、超大正文和录制请求返回明确拒绝，半包到期不会调用截图业务。
CLI 延迟在参数阶段限制为零至六十秒，JSON 中的负延迟按原版归零。

## 验证边界

- 本次 JSON 字段兼容 Qt，套接字按 Wayland 合成器隔离，不与 Qt 地址互通
- 本次只覆盖普通截图生命周期，托盘常驻和全局快捷键流程仍需补齐
- 双输出验证确认参数、表面数量与交付尺寸，混合比例的全部像素审计仍未完成
- 命令耗时记录为创建子进程后的确认等待，不代表冷启动时间
- 空闲资源属于这些明确场景，不代表全部工具、冷启动或其他合成器
