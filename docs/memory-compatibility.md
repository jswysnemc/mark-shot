# 内存对照与验收范围

正式目标覆盖 Wayland 与 Windows。原内存要求为同场景稳定内存与峰值低于 Qt 的一半，
不降低图像分辨率、颜色精度或功能。该完整验收尚未通过；2026-11-07 最新目标要求
结束继续优化，选取此前较优方案，浅色主题和 Windows 工作提升为最高优先级。

选用候选为 R20，七组非工具原生流程与三组主题回归通过；十一项工具有效对照中仍有超标
指标，文字尚未验证。选用依据和封存输入见 [R20 方案](selected-memory-scheme.md)。
R17–R18 的消费契约、连续帧、实际总量与失败项见
[前景消费验证](frame-consumption-memory-verification.md)；R14–R16 见
[原生帧验证](native-frame-memory-verification.md)。下文保留各历史候选的原始结果。

使用私有 Sway 的 3840×2160 一倍输出和确定性原生滚动页面，隔离配置、数据目录、
剪贴板与套接字。产品进程及所属子进程计入 RSS、PSS 和私有内存；测试页面、合成器
与测量脚本单独运行，不计入应用。25 毫秒采样用于观察阶段峰值，主进程 VmHWM
补充内核峰值；采样峰值不代表所有瞬时 PSS 峰值。

阶段覆盖启动、稳定编辑、滚动增长、暂停、结果编辑或导出和退出。输出必须保留
完整原始像素，取消必须恢复底层页面并释放本次资源。原始样本以 JSONL 保存，
结果按二进制指纹绑定；失败现场保留，不把旧候选结果归到新候选。

运行器与采样代码分别为 `scripts/wayland_text_sway_runtime.py`、
`scripts/wayland_memory_metrics.py` 与 `scripts/wayland-memory-baseline.py`。
此前 1280×800 编辑空闲数据不足以推断 4K 或长截图占用。

## 第一轮实现

预览改用拼接缓冲的借用视图，横向输出交换读取坐标，不创建完整转置快照。
进入长截图后释放旧冻结原图、遮罩、标注与其他输出画布，原生表面关闭后重建空共享池。
结果交接先释放旧编辑器，再创建新编辑器。原始长图只在交付时转换一次 RGBA。

拼接器双轴、增长、重访和前插视图回归通过；32 项滚动单元测试通过、1 项忽略。

Rust 稳定 RSS 为 383.6 MiB，观测峰值为 461.3 MiB；仍未满足要求。

## 增长缓冲与角色预算

## 当前边界

稳定内存、观测峰值与内核峰值仍高于 Qt 的一半。普通 4K 和结果编辑尚未解决，
后者需要继续减少整屏绘制层与原始图像副本。不同轮次的 Qt 占用有变化，因此每轮
按其自己的 Qt 结果计算比例，不使用较高的历史基线判断达标。

当前实际环境为私有 Sway。其他 Wayland 合成器、完整工具与多输出矩阵、复制和贴图
峰值、OCR 及 Windows 原生工作流尚未完成这一验收。后续候选保持独立指纹与清单，
不替换上述原始记录。
