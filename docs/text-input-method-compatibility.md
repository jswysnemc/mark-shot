## 原版实际行为

探针使用 `QInputMethodEvent` 直接驱动原版 `QTextEdit`，读取文档、光标、选区、布局中的
预编辑区、输入法查询与撤销状态，不手写原版业务结果。源码和构建对象保持不变；
只读链接 395 个对象，过期依赖为零。最新证据位于 `target/qt-text-input-method-expanded/`，
固定样本为 `tests/fixtures/qt-text-input-method.json`。

- 候选从 `ni` 更新为 `nih` 不改变正文，也不增加撤销记录；取消候选仍保持原正文
- 没有候选、确认或删除的空事件不修改正文，也不清除原字符选区
- 开始在选区内组合时，Qt 立即删除选中文字；取消候选不自动恢复，撤销才恢复原内容
- 选区删除和随后确认候选属于不同撤销动作；恢复选区删除后光标收起，不恢复原字符选区
- 两次输入法确认 `你`、`好` 可以分别撤销，不能合并成普通键盘连续输入组
- 同一个输入法事件可以确认 `你` 并开始下一段 `hao` 候选，正文只包含已确认部分
- 确认时的相对替换使用 Qt UTF-16 位置；UTF-8 多字节长度不能直接套入 Qt 的替换长度
- 多行文档的绝对光标与当前段落上下文光标不同；样本中绝对位置为五，上下文位置为一
- 跨段落选区的 Qt 上下文锚点可以是负数，样本为负六；它不能直接作为 Wayland UTF-8 锚点发送
- 扩展汉字占一个 Unicode 码点、两个 UTF-16 单元和四个 UTF-8 字节，确认与替换必须分别换算
- 直接提交标注不把尚未确认的候选写入成稿，空正文也不产生持久标注

探针的失焦场景使用隔离的 offscreen 平台，没有真实输入法上下文。布局中的候选在
该场景失焦后仍存在，不能由此推断真实 Wayland 离开事件应保留候选；协议明确要求
客户端在 `leave` 时重置预编辑。私有 niri 菜单和 Sway 窗口切换已验证原生离开重置。

## 协议与字节边界

参考锁定的 `wayland-protocols 0.32.13` 所带协议 XML，以及
[text-input-v3 协议说明](https://wayland.app/protocols/text-input-unstable-v3)。
当前两种私有合成器提供的是一版接口，不能直接调用新版才提供的动作或样式请求。

`types/text_input.rs` 将候选、确认、前后删除和焦点目标分开传递。候选内部光标采用
UTF-8 字节位置，两个负一表示隐藏；默认零位置与显式隐藏不是同一状态。反向候选
范围保留两个端点，不能提前把它压成无方向区间。

`features/text/input_method/positions.rs` 在文档字节和编辑器行位置之间换算。码点中间
字节、超出文档或极端索引返回无效结果，不发生溢出。删除请求必须同时验证光标和
前后端点，不能因两个端点恰好合法而接受位于码点中间的光标。

`features/text/input_method/surrounding.rs` 最多复制四千字节，保留完整选区和光标，
裁切不会分割 UTF-8 码点。超长选区或无法编码为协议字符串的上下文返回不支持，
不得发送伪造的部分选区。原生同步在支持能力变化时停用再启用，清除旧上下文，
而非仅省略新请求。借用窗口用于比较，只有实际状态变化才复制最多四千字节。
同段落使用 Qt 段落范围，跨段落使用文档字节位置，避免把负数段落锚点转换成
无符号协议位置。

`features/text/input_method/transaction.rs` 暂存候选、确认和删除，到 `done` 才交付；
后续事件替换同类暂存数据。交付和焦点重置清空全部暂存值，不重放上一批的候选或
删除。非法候选不能丢掉同批合法确认文字。旧 `done` 序号仍交付文字，但不允许按
过期状态重发协议上下文。原生层按对象提交序号查找原字段身份，旧字段的批次不能
因接收时已经启用新字段而改投新目标。相同字段的旧序号仍交付内容；匹配序号到达
后才同步状态，排队消息交付时再次核验实际提交计数。

## 生产组合与同步

`tools/text/layout.rs` 会比较标注正文和编辑器缓存正文，二者不同就重新同步内容。
因此不能只把候选插入现有缓存而仍用已确认标注绘制；下一帧会清除候选。反过来，
把候选写入 `Session.working` 也不正确，提交和导出会把未确认文字当作成稿。
`editor/text_composition/` 用独立候选标注与缓存显示预编辑，`Session.working` 和普通
编辑器只保存已确认正文。候选变化才更新显示预览，闪烁帧不重建或复制全文。

`editor/text_session_history.rs` 当前普通输入可合并，输入法确认必须使用独立动作。
首个非空候选导致选区删除时应记录真实删除；后续候选变动不追加正文历史。空事件
保持选区，取消候选只撤除预览，不能无条件回填原选区。协议的目标身份还必须独立于
复用的预览标注编号。每次正文会话、原生焦点和字段重启分别分配身份，过期批次整体丢弃。

```text
backend/wayland/text_input/
  mod.rs              可选管理器、每个键盘 seat 的对象与请求发送
  state.rs            状态差异、提交计数与字段序号边界
  events.rs           候选、确认、删除、进入与离开分派
app/text_input.rs      正文资格、段落上下文与表面逻辑光标矩形
features/text/input_method/focus.rs
                      会话与原生焦点目标生命周期
editor/text_composition/
  apply.rs            完整校验替换范围与独立撤销
  preview.rs          候选显示、局部损坏与取消
renderer/text_preedit.rs
                      字体装饰度量与候选下划线
```

字体、颜色字段、识别界面和原生菜单拥有输入时停用正文协议。普通键盘失焦本身
不取消候选，原生 leave 才重置；协议缺失时保留普通键盘输入。光标矩形来自显示
编辑器并转换为表面逻辑坐标，不把像素缩放乘入协议位置。显式隐藏候选光标停止
定时唤醒，恢复可见候选重新计时。

Sway 的 layer 菜单只停用正文，不一定发送 text-input leave；niri 菜单会发送。
因此菜单取消与真实表面离开分开核验。Sway 真实失焦后仍保留对象启用标志，重新
enter 时先提交 disable，再 enable 和完整上下文。只清理本地状态再 enable 会使
输入法保持停用，修改前生产失败保留于 `target/ime-sway-r7/window/native-leave/`。

## 验证边界

基础测试位于 `tests/text_input_method.rs`，覆盖多行与组合附加符、双向选区、上下文
裁切、前后删除、隐藏光标、批次清空及旧序号。生产组合测试比较十七组、77 个实际
Qt 状态，并验证候选帧、取消恢复、透明背景、分数比例和显示缓存复用。

此前正文专项的私有配置工作区 738 项测试通过、10 项忽略，Python 114 项通过；全部目标和
功能的严格 Clippy、格式与新增脚本 Ruff 检查通过。当前索引为
`target/verification-text-input-native/result.json`；基础阶段索引继续保留，不混用发布指纹。

首次十三组探针保留于 `target/qt-text-input-method/`。修改前失败分别保存于 `target/text-input-foundation-before.log` 和
`target/text-input-cursor-boundary-before.log`。工作区和严格检查日志使用
`target/text-input-foundation-*.log`，不替换光标阶段已验证的 release 证据。

私有 niri 与 Sway 的 layer、window 四种组合共验证 21 个场景，包括真实候选投递、
确认和下一候选共存、四字节扩展汉字、字节删除、逐次撤销重做、字段停用、菜单取消、
未确认候选排除导出及真实原生离开恢复。隐藏光标期间单线程、CPU 时钟不增加，
没有画布提交；候选导出与无候选基准逐像素相同。两个既有光标场景也在同一发布
构建重新通过。证据位于 `target/ime-niri-final/` 与 `target/ime-sway-final/`。

测试输入法是从锁定 XML 编译的开发用 input-method-v2 客户端，不进入发布依赖，
不等同于 Fcitx、IBus 或全部输入法实现的实际配置验证。截图字段后续验证见字段专题；
OCR 结果、历史和文件窗口仍未接入，完整 Unicode、文字缩放换行和 Qt 逐像素一致仍需覆盖。
