# Wayland 共享内存修复复核

[English](../wayland-shm-audit.md) | **简体中文**

2026-11-19 复核 `e2153b7`，对应 [Issue #175](https://github.com/jswysnemc/mark-shot/issues/175)。无收缩密封共享文件的分配迁移已覆盖已检查的呈现与捕获路径，但两个既有配置回调仍绕过了缓冲生命周期接口。本次补齐调用路径与协议回归，继续保留 Issue 打开。

## 分配与释放范围

| 路径 | 分配与释放方式 | 复核结果 |
| --- | --- | --- |
| 截图覆盖层、冻结背景、滚动子表面 | 本地 `SlotPool`，通过 `attach_to` 登记占用 | 已迁移；探测配置和滚动父窗口回调另有下述遗漏 |
| 贴图、预览、菜单、普通窗口 | 本地 `SlotPool`，活动缓冲丢弃后等待 `wl_buffer.release` | 没有发现残留的 Smithay 共享内存池 |
| 原生 screencopy 与 image-copy 截图 | 本地 `RawPool`；捕获结束销毁缓冲和协议对象 | 使用相同的无收缩密封文件创建入口 |
| Wayland 录制的软件缓冲 | `tempfile::tempfile()`、独立 `wl_shm.create_pool`；帧协议完成后读取，所有者退出时销毁缓冲 | 普通临时文件不具备收缩密封条件，不属于遗漏的密封 memfd |
| 光标 | `wp_cursor_shape` 协议 | 没有客户端主题像素池需要迁移 |

`RawPool` 只传入 `MFD_CLOEXEC`。Linux 返回的 memfd 自动含 `F_SEAL_SEAL`，不含 `F_SEAL_SHRINK`，并永久拒绝追加收缩密封。其作用是阻断要求 `F_SEAL_SHRINK` 的 UDMABUF 导入条件；“无密封”并不表示 `F_GET_SEALS` 必须返回零。

本地实现的活动计数、额外逻辑引用、延迟销毁和连接退出兜底，与锁定的 Smithay Client Toolkit 0.21.1 实现核对后，没有确认新的底层计数缺陷。协议测试进一步检查服务端收到的描述符、真实释放事件和客户端实际发送的销毁请求。

## 已补齐的调用路径

1. `overlay/state/layer.rs` 的显示器探测表面直接附着 `wl_buffer`，未调用 `activate`。客户端因此把已提交的像素视为空闲，丢弃所有者时立即销毁缓冲并归还槽位。本次改用 `attach_to`，在真实释放事件到达前保留活动状态，错误写入配置结果。
2. `overlay/state/xdg.rs` 的滚动父窗口先调用 `configure_surface`，该方法已按尺寸初始化并附着缓冲；随后回调又清零并直接附着同一缓冲。首次配置产生两次附着，重复配置也可能重新提交仍活动的缓冲。本次只提交窗口几何状态，像素分配与附着统一交给 `configure_surface`。

两处代码均在 `e2153b7` 之前存在，该提交迁移共享池时保留了它们。本次同时移除 `ShmBuffer` 和槽位 `Buffer` 暴露的原始协议缓冲访问方法，防止呈现代码再次绕过活动登记。

## 回归验证

新增八项自动测试，通过 `UnixStream::pair()` 和私有 `wayland-server` 建立真实协议连接。服务端按测试指令发送配置和释放事件，不连接用户桌面，不使用图形驱动，也不要求启动合成器。服务端角色处理与共享内存处理分别独立成文件；新增依赖仅用于 Linux 测试。

修复前运行 `cargo test --lib shm_lifecycle_tests -- --nocapture`，三项配置回归均失败：

- 探测缓冲提交后 `active()` 为假。
- 父窗口首次配置的附着记录为 `[0, 0]`，预期为 `[0]`。
- 父窗口调整尺寸后的附着记录为 `[0, 0, 1, 1]`，预期为 `[0, 1]`。

五项内存池生命周期测试在修复前通过，检查释放后恢复可写、丢弃活动缓冲延迟销毁、同槽位多个缓冲全部释放、连接退出回收，以及报告尺寸 `2561 × 1440` 的连续 32 帧复用。连续帧测试确认扩容后仍不含收缩密封，容量和偏移不随已释放帧数增长。

修复后八项新增回归通过，可分别运行：

```sh
cargo test --lib shm_lifecycle_tests
cargo test --lib shm_pool::lifecycle_tests
```

工作区测试共 1765 项通过、0 项失败，46 项按原有网络、模型或平台条件忽略。Linux 工作区全目标 Clippy（`-D warnings`）、Rust 格式检查和差异空白检查通过。

## Issue 状态与验证边界

这些结果确认应用侧缓冲生命周期遗漏已经补齐，不能证明 Issue #175 报告的内核孤儿页锁定已经停止。探测像素和滚动父窗口的调用错误，也不足以解释报告中每次会话增加 31 至 53 个整屏帧的页锁定现象。

报告中的 Fedora 44、KWin、内核 `7.0.13-200.fc44.x86_64` 和 AMD Radeon 680M 组合尚未复测。Issue 继续打开，仍需使用包含修复的构建，通过 `scripts/check_foll_pin.py` 检查取消、复制、贴图及进程退出后的 acquired/released 增量。私有协议测试、其他合成器验证或无操作采样校准均不能替代该环境的证据。
