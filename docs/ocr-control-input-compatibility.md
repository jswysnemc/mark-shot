# OCR 结果按钮输入对照

## 原版证据

`tests/fixtures/qt-ocr-control-reference/main.cpp` 只读链接原版 `OcrResultWindow`，直接操作
实际 `QPushButton` 和 `QTabBar`。复制按钮从标题栏定位，撤销按钮从 `ocrSourcePane`
定位，避免误选隐藏译文区的同名按钮。所有可操作目标在测试前必须可见。

Qt 6.12.0 离屏记录包含 36 个场景，冻结到 `tests/fixtures/qt-ocr-controls.json`。
记录每次事件后的正文、焦点、按下状态、点击次数、窗口可见性和剪贴板内容。
探针使用临时配置，并清除真实显示服务器和座席环境，不修改原版源码、构建对象或用户配置。

## 已实现规则

- 复制、撤销、关闭按钮在左键按下时只记录事务，原按钮内部释放才执行；移出后释放取消。
- 移出时暂停按下外观，重新进入后恢复；原生窗口失焦或内部焦点改变取消事务。
- 右键和中键只获得按钮焦点，不执行操作；已有左键按钮抓取期间的右键不启动正文菜单。
- Space 包括 Ctrl、Shift、Alt、Meta 修饰组合都等待释放，自动重复按下不重复执行。
- 原版结果窗口不是对话框，按钮不是默认按钮，普通 Return 不执行按钮操作。
- 无修饰键 Escape 关闭普通结果窗口；修饰键组合不匹配关闭快捷键。菜单的 Escape 契约单独处理。
- 页签不是按钮，左键按下仍然立即换页；右键只获得页签焦点，不换页。
- 禁用复制按钮的点击将焦点交给父窗口，不继续向正文写字；全空白原文不启用全文复制。
- 最后一项原文撤销后隐藏撤销按钮，非空白正文的焦点转向复制按钮，与实际 Qt 记录一致。
- 复制资格借用编辑器行文本，不在每次按钮重绘时分配完整正文副本。

正文、父窗口、页签和按钮分别有明确焦点身份。只有当前内容编辑器具有输入法资格，
按钮或父窗口焦点不能接受候选或确认。按下外观使用原版暗色背景，不把按钮按下当作已选页签。
状态更新不添加定时器或驻留工作线程。

## 文件职责

| 文件 | 职责 |
| --- | --- |
| `src/features/ocr_result/control_input.rs` | 控件资格、焦点身份和指针、键盘事务 |
| `src/features/ocr_result/control_input/tests.rs` | 取消、修饰键、禁用资格及冻结 Qt 序列回放 |

## 验证边界

原生测试逐事件回放十三组实际 Qt 关闭、Return 和 Escape 场景，另覆盖左键释放、失焦、
禁用输入资格、页签职责、修饰键 Space 和 Unicode 空白。真实桌面回归检查按下中间状态、
移出释放、右键焦点、Return、Ctrl+Space、修饰键 Escape、关闭释放和持久剪贴板。
预览版 5 的下载二进制在新增真实回归中复现“Copy 在按下时执行”，失败证据保留。

这些结果不代表完整 OCR 窗口已经一致。现有工具栏几何、所有按钮与图标、完整 Tab 和方向键
焦点遍历、页面焦点恢复、反馈计时、全部主题和逐像素对照仍需补齐。
原图交互和独立表格复制入口的后续对照见 `docs/ocr-source-preview-compatibility.md`。
更多入口的父子菜单和逐层导航另见 `docs/ocr-more-menu-compatibility.md`。
原版的翻译和独立置顶入口不因本轮按钮输入测试而视为完成。多设备混合按键和真实
Fcitx/IBus 也没有全面验证。
