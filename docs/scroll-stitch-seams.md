# 滚动截图阴影接缝处理

## 现象与现有实现

目标是消除长图内部反复出现的横向阴影，同时保留文字、边框和页面本身的阴影。

当前 `crates/shot-stitch/src/fixed_regions.rs` 从画面上下边缘逐行比较两帧相同屏幕位置的像素，遇到差异超过 `ROW_MAX_DIFF` 就停止。`algorithm.rs` 使用该结果计算 `bottom_trim`，`long_image.rs::append` 再用新帧替换已有长图末端的对应行。

该流程可以识别不透明的固定底栏。底栏上方的半透明阴影则混合了后方正在滚动的正文：阴影位置固定，像素值仍然随正文变化。因此固定区域扫描可能在阴影内部或阴影下方停止，旧帧中未替换的阴影就会周期性留在长图里。参考截图与这种情况相符；仅凭成品长图还不能确认每条横线都来自底栏阴影，需要原始连续帧验证。

已接入**重叠区像素校验、正文区域选缝、边缘原像素替换**。两帧合成回归在修改前稳定发现第 248 行残留阴影，修改后通过；四类 Chromium 页面连续帧也通过逐像素对照。用户原始页面仍需用实际连续帧验证。

## 文件结构

```text
crates/shot-stitch/src/
├── fixed_regions.rs       保留现有固定区域主体检测
├── edge_occlusion.rs      分块比较正文行差异及纹理强度
├── seam.rs                复核位移，在连续匹配正文中选择连接位置
├── adjacent.rs            提供排除视口两端的备用位移候选
├── algorithm.rs           串联位移估计、遮挡检测、选缝与提交
└── long_image.rs          复用现有分块替换接口和缓存修订逻辑
crates/shot-stitch/tests/
└── shadow_seams.rs        渐变阴影、透明底栏、双轴双向及补采恢复
tests/
├── scroll_shadow_browser.rs  浏览器原像素、应用会话和分块交付验证
└── fixtures/scroll-shadow/   脱敏页面、连续帧与无浮层参考图
scripts/scroll-shadow-fixtures.py  独立 Chromium 会话生成浏览器样本
```

末帧尾部保留在已有分块原图中，后续拼接允许替换，因此不需要额外尾部缓存或完整帧历史。

## 处理流程

1. **先估计位移，再校验原像素。** 沿用多带签名和运动区域，比较范围使用 `MotionMask::moving_span`。候选位移缺少足够连续匹配正文时，再尝试上一帧位移和排除视口两端四分之一后的中心候选。只有原始像素匹配达到 `min_overlap` 才采用替代候选，防止重复卡片和上下阴影诱发错误位移。

2. **标记不一致行。** 把同一正文行分成八块，每块最多采样 32 个像素，比较 RGB 通道绝对差异，任一块均值超过 1 就不能作为干净匹配行。该比较同时覆盖黑色阴影、亮色阴影与透明模糊底栏；分块最大差异避免局部阴影被整行平均稀释。原有固定区域检测用于先排除不透明头尾。

3. **选取连续正文证据。** 页面自身的阴影随正文移动，对齐后仍一致，因此会保留。候选匹配段至少包含八行可辨认纹理，不能只凭空白或恒定色底栏通过。连接要求连续匹配行数达到 `min_overlap.clamp(8, 32)`；覆盖整段评分或重访锚点时，要求达到完整 `min_overlap`。

   分数缩放可能让同一正文产生不同采样相位。严格匹配不足时，额外比较相邻两张原始帧：整段每块绝对差异不超过 12、每个通道的有符号均值差不超过 3，且纹理和长度足够，才沿用原边界追加。该分支避免无故替换已有正文；不能用混合了多次采样相位的长图替代上一张原始帧。阈值来自脱敏的 1.2 倍 Wayland 采集回归，其他渲染器仍需实际验证。

4. **在匹配段中部连接。** 选择最长可信匹配段，舍弃两端各四分之一，在中间区域选纹理较低的行，同等条件下靠近中心。这样连接位置远离阴影衰减边界。连接以前保留原图，从连接位置开始复制新帧原始像素，同时更新行签名和缓存修订号。当前采用全宽水平连接，没有模糊、提亮或跨帧混色。

5. **保留真实首尾。** 新帧底端仍可能有阴影，暂时留在长图末尾，下一帧会替换该区域。结束时保留最后一次底栏及其真实阴影，头部固定区域同理只保留一次。向上滚动使用对称逻辑，横向滚动沿用现有转置坐标。

6. **覆盖不足时保留原图。** 没有可信连接位置时不增长、不覆盖原始像素，也不让错误的微小位移改变待确认滚动方向。界面提示“重叠不足，请缓慢回退”。返回有足够重叠的位置后可以继续。当前捕获由用户滚动驱动，没有新增自动控制滚动步长。

## 连接坐标与内容完整性

以下以向下滚动为例：旧帧正文起点为 `P0`，新帧起点为 `P1 = P0 + d`，帧高为 `H`。两帧分别排除顶部 `t0/t1` 和底部 `b0/b1` 行，干净区为：

```text
旧帧干净正文区：[P0 + t0, P0 + H - b0)
新帧干净正文区：[P1 + t1, P1 + H - b1)
可选连接区：上述两个区间的交集
```

在交集内部选择全局正文行 `S`，连接前半部分保持不变，后半部分从新帧的 `S - P1` 行复制。用正文坐标决定替换和增长量，而不是每帧直接减去固定高度。这样消除遮挡不会跳过对应正文，也不会重复行。

直接使用现有 `append(frame, cols, rows, trim)` 和 `prepend` 执行连接位置替换。新增行数减去替换行数始终等于实际增长量。像素行、行签名、`anchor`、统计高度和缓存修订号保持同步；预留空间沿用分块行存储，不创建整张长图的临时副本。

## 首尾处理与能力边界

- 固定底栏与阴影不应在正文内部重复出现。当前输出保留真实首尾一次，不默认裁掉最后一个底栏或首个固定头部。
- 到达页面末尾后，若某段正文在所有帧里始终受到遮挡，仅凭截图不能无损恢复它。当前保留真实尾部，用户可在编辑阶段裁切。
- 若接入浏览器专用捕获，可以在获得页面控制能力后临时隐藏已确认的固定元素再采集，并在结束或异常时恢复样式。通用桌面截图没有 DOM，不能依赖这种方式。
- 已经导出的长图缺少原始连续帧时，无法保证消除灰带的同时恢复原始文字与颜色。本方案主要防止采集时产生新的拼接痕迹。

## 验证与验收

合成测试覆盖 128 组双轴、双向、四种步长与四种阴影组合，另验证固定区检测边界、覆盖不足后的恢复、重访、切换增长方向、底栏外观动态变化和均衡重采样误差。所有正文逐行比较原始像素，最终尾部比较末帧真实像素。

Chromium 样本覆盖浅色、深色、透明模糊底栏及上下同时悬浮四种页面。每种页面保存四帧和无浮层参考图，验证生产拼接器、`ScrollSession` 去重接收、预览和分块交付。固定样本不依赖测试机器安装浏览器或字体，更新样本需要 Chromium 和 agent-browser。

`fractional` 目录另存三张隔离 Wayland 会话的真实采集帧，使用 1.2 倍缩放和翻转输出。逻辑滚动 48 像素后物理位移交替为 58、57 像素，测试要求持续增长且已经提交的正文原像素不变。样本来自 `scroll-page` 的确定性纹理，不含用户桌面内容。

隔离 Sway 的 1 倍输出另验证实际采集全流程：空闲后继续滚动、横纵向、预览避让、暂停恢复、返回编辑、复制、保存和取消。导出结果与原始帧组合逐像素一致。1.2 倍输出目前使用上述连续帧回放验证；既有全流程脚本按固定物理步长组合参考图，不能据此宣称完整分数缩放矩阵已通过。
